# Component catalogue

The shared components this skill ships as templates (`templates/src/ui/`), what each one is for,
its role, the parts it derives from its `testID`, and the flags the checker reads. The same list,
machine-readable, is the app's `contracts/component-library.json` (template in
`templates/contracts/`); the app edits that file as its library grows. Anatomy, states and the
do and don't of each component are in [actions-and-inputs.md](actions-and-inputs.md) and
[lists-surfaces-and-overlays.md](lists-surfaces-and-overlays.md).

## Before the components: prerequisites

The components import these files; `check-components.mjs` fails `prerequisite-missing` when one is
absent, naming the skill that creates it. Set them up first.

| File | Gives | Created by |
|---|---|---|
| `src/theme/tokens.ts`, `type-styles.ts`, `motion.ts` | `SPACING`, `RADII`, `STROKE`, `ELEVATION`, `MIN_TOUCH`, `PRESS`, type roles and styles, `MOTION_MS`, `EASING`, `SPRINGS` | design-system-structure |
| `src/theme/make-styles.ts`, `use-theme.ts`, `shadow-styles.ts`, `use-text-locale.ts` | `makeStyles`, `useTheme`, `shadow()`, the layout direction | design-system-structure |
| `src/ui/app-text.tsx` | `AppText`, the only text renderer (variants, tones, `isHeader`, `language`) | design-system-structure |
| `src/ui/pressable-surface.tsx` | `PressableSurface`, the one press implementation (the press look is `PRESS.kind`) | design-system-structure |
| `src/ui/press-feedback-context.tsx` | `usePressFeedback`, the injected tap sound or haptic | design-system-structure |
| `test/render-with-providers.tsx` | `renderWithProviders` for every component test | unit-and-component-tests |
| `test/a11y/find-inaccessible-pressables.ts` | the audit each component test ends with | accessibility-as-code |

A catalogue may add entries (`prerequisites`) and give one a `mustContain` marker, for example a
type style the strong rows need, so an old copy is reported as old.

Copy the ones the app needs, each with its test. A component that renders another (ListRow renders
IconTile, Toggle, RadioMark and Chevron) needs those too; `tsc` names any that is missing.

**Settings rows.** settings-and-preferences' example names row primitives the library builds from
these components rather than shipping under those names: a switch row is `ListRow kind="switch"`
(`isOn`), a link row `ListRow kind="navigate"` (`value`, the chevron mirrors), a danger row `ListRow`
with `isDanger`, a section header `SectionHeader`, a segmented row `SegmentedControl` and a slider
row `Slider` inside a `ListGroup`, and a confirm dialog `Scrim` + `DialogCard` + `DialogButtonRow`
(safe choice first). An app that wants the short names wraps them in one feature file, or adds
them as catalogue entries with their own tests.

## Owned by other skills

| Part | Where | Owner |
|---|---|---|
| AppText, PressableSurface, the press feedback context | `src/ui/` | design-system-structure (prerequisites, never library components) |
| The reduce-motion store and hooks, announcements | `src/ui/a11y/` | accessibility-as-code (excluded from the catalogue by `exclude`) |
| The icon set (`Icon`, app icon, splash) | `src/ui/icons/` | icons-app-icon-and-splash (excluded by `exclude`) |
| The motion moments, `CelebrationBurst` and `BurstPiece` | `src/ui/motion/` | motion-and-animation (excluded by `exclude`) |
| `ScreenFrame` (safe areas, the content column) | `src/ui/screen-frame.tsx` | react-components-and-hooks (owned elsewhere by default) |
| `SubtreeErrorBoundary` (a class on purpose) | `src/ui/subtree-error-boundary.tsx` | react-components-and-hooks (owned elsewhere by default) |
| `PhysicalDirectionView` (a surface that never mirrors) | `src/ui/physical-direction-view.tsx` | rtl-and-direction (owned elsewhere by default) |
| `ScreenBody` (the scrolling page body of a screen contract) | `src/ui/screen-body.tsx` | screen-contracts (owned elsewhere by default) |
| `AdBannerSlot` (the real ad slot; the catalogue's ad placeholder is `mockOnly`) | `src/ui/ad-banner-slot.tsx` | admob-ads-and-consent (owned elsewhere by default) |
| `ListDetailLayout` and the pane maths | `src/ui/adaptive/` | adaptive-layout (excluded by `exclude`) |
| Form fields (`TextField`, `FieldNote`, `KeyboardDoneBar`) | `src/ui/form/` | forms-and-input (they join this catalogue: that skill ships their entries) |
| The notice host, confirmation dialog, state messages, offline banner, skeletons | `src/ui/feedback/` | ui-states-and-feedback (excluded by `exclude`; with a catalogue they compose `Toast`, `Scrim` + `DialogCard`, `EmptyState`) |

Owned-elsewhere files are never discovered, never make the checker ask for a catalogue, and are
never `component-unlisted`; the app-wide press rules still read them. Another skill's single file in
`src/ui` joins the defaults through the catalogue's `ownedElsewhere` (`{ "file":
"{uiDir}/<file>.tsx", "owner": "<skill>" }`); a whole folder goes under `exclude` (which replaces
the default list, so keep `a11y/**`, `icons/**`, `motion/**`, `adaptive/**` and `feedback/**` in
it). Listing one of these files under `components` checks it as a library component after all.

**Confetti or CelebrationBurst.** One celebration per moment, never both. Confetti is this library's
full-width band that scatters a few pieces across the top of a screen for a screen-level moment
(every task done, a list finished). A burst from the point of action (inside the checkbox that was
just ticked) is motion-and-animation's `CelebrationBurst`, which also owns the moment catalogue and
its limits. An app that adopts motion-and-animation's moment catalogue drops Confetti (its
checker requires a celebration to play through `useCelebration`), swaps BusyIndicator for the
`useMotionLoop` example and lists the Toggle, Toast and hold files in moments: the table is in
building-a-component.md, "With motion-and-animation's moment catalogue".

## Mock-only parts: never build

A design file often draws stand-ins: an ad box, an OS permission or consent sheet, a placeholder
for a canvas the app draws elsewhere. List each under `mockOnly` with the reason; the checker fails
`mock-only-built` if one is built. The template lists an ad placeholder (the ads SDK renders the
real banner: admob-ads-and-consent) and a consent sheet (the consent SDK and the OS draw it).

## Games

Game parts (level tiles, star ratings, a game's top bar, score panels) are not in this core
library: game-session-host hosts a game and owns them. They follow the same rules (catalogue,
required testID, derived parts, a test each) and can join the app's catalogue.

## When multi-package

In a monorepo the shared components usually live in a UI package (`packages/ui/src/`). Point the
scripts at it: `--ui-dir packages/ui/src` and `--contract packages/ui/contracts/component-library.json`,
or set `uiDir` in the catalogue and `componentLibraryContract` in `rn-skills.config.json`. The
checker scans every workspace's source folders (from `package.json` `workspaces`) for second press
implementations; the UI package imports the theme from its own package or `@<org>/theme`.
