## The decision, with measurements

Every UI icon is data: one SVG path per icon on a 24-unit grid, filled with the nonzero rule, in
`src/ui/icons/icon-paths.ts`. `Icon` rasterizes the path with Skia on the CPU (`Skia.Surface.Make`)
into a white PNG at the exact pixel size (`size x PixelRatio.get()`), caches it as a
`data:image/png;base64,...` URI, and shows it in a native `Image` tinted with `tintColor`. Colour comes
from the theme at display time, so a theme or dark-mode change never re-rasterizes. React Native decodes
`data:` URIs locally: no network is involved.

| Option | Verdict | Evidence (Release build, iOS simulator, a grid of 90 tiles with icons) |
|---|---|---|
| Skia `<Canvas>` per icon | Rejected for icons; kept for a few multi-colour pictures per screen | 264 to 280 ms to lay out, +16 MB (about 0.18 MB and 2.8 ms per canvas) |
| **Skia path rasterized to a tinted `Image`** | **Chosen** | 58 ms, +1 to 2 MB; rasterizing 2 icons took 0.4 ms |
| react-native-svg for UI icons | Rejected for icons; fine for charts, graphs and illustrations | a second icon path next to the set: no tint from the theme, no RTL flip, no hidden-from-screen-readers default, glyphs outside the layers file. `check-icons` does not ban the package (a chart is a legitimate use); an icon drawn with it is a review finding |
| Icon fonts, vector-icon packages (`@expo/vector-icons`, …) | Rejected | glyphs the design does not own, a font to load before the first frame, and names a checker cannot match to a design source |
| SF Symbols (`expo-symbols`) | Opt-in only | iOS-only (Android needs a second set); allowed for native tab bars through `contracts/app-art.json` `icons.allowPackages` |
| Plain Views | Only for trivial shapes (dots, bars) | cannot draw a gear, a bell or a lock |
| Emoji, image files | Rejected | emoji differ per OS version and are read aloud by name; files are not drawn from the design source |

The measurements were taken in the production app this skill was generalized from (2026-09, iOS
simulator, Release); Android was not measured. Icons at 24 pt on a 3x screen become 72 px PNGs of 0.3
to 1.4 KB.

## The grid and the layer model

- `viewBox 0 0 24 24`, one colour. Default size 24 pt.
- Each icon in `design/icon-layers.json` is a list of **layers** drawn in order in one colour:
  - `{ "op": "stroke", "width": 2, "cap": "round", "join": "round", "d": "..." }`: a line (round caps and joins);
  - `{ "op": "fill", "fillRule": "nonzero", "d": "..." }`: a solid shape;
  - `{ "op": "fill", "fillRule": "evenodd", "d": "..." }`: a shape with a hole (the lock's keyhole);
  - a filled shape that should look soft gets a second layer, `stroke 1.4` with a `butt` cap and
    round join over the same path (it rounds the corners).
- Stroke widths of the shipped set: 2 regular, 2.4 bold (check, close, plus, chevron), 1.4 on filled
  shapes, 1.6 for a star edge. Strokes scale with the icon. One family of widths is what makes a set
  look designed: pick yours once and keep it.
- Rects and circles are written as exact path data (arcs), so every layer goes straight into
  `Skia.Path.MakeFromSVGString`.
- `"directional"` lists the icons that point along the reading direction (see Mirroring).
- The shipped set is the neutral one in [icon-catalogue.md](icon-catalogue.md): replace or extend it.

## From layers to one path: build-icon-paths.ts

`Icon` fills one nonzero path per icon, so the layers are flattened at build time by
`scripts/art/build-icon-paths.ts` (headless Skia on CanvasKit, Node type stripping):

1. Each stroke layer becomes an outline: `Skia.Path.Stroke(path, { width, cap, join: round })`.
2. An even-odd fill keeps its rule: `Skia.PathBuilder.MakeFromPath(path).setFillType(EvenOdd).build()`.
3. All layers are unioned: `Skia.Path.MakeFromOp(a, b, Union)`.
4. The union is converted to the nonzero rule: `Skia.Path.AsWinding(union)`. Path ops return
   even-odd paths and an SVG string loses the fill type; without this step outlined shapes (a ring, the
   info circle) fill solid.
5. Numbers are rounded to 2 decimals (0.06 px at 3x: invisible, about half the size).
6. The file is written exactly as Prettier prints it (keys unquoted when they can be, long entries
   broken after the key unless the key is shorter than 5 characters), so `--check` compares bytes and
   the formatter never rewrites it. Line 2 is `// GENERATED by scripts/art/build-icon-paths.ts ...`:
   test-edit checks (tdd-workflow) exempt generated files by that line, and `check-icons` fails
   `generated-header` without it.

Skia enums are passed as numbers (the script imports Skia types only): `StrokeCap` Butt 0, Round 1;
`StrokeJoin` Round 1; `FillType` EvenOdd 1; `PathOp` Union 2. Skia 2.6.2 uses the `Path.*` factory and
`PathBuilder` APIs; the older `SkPath.stroke()`, `makeAsWinding()` and `setFillType()` log deprecation
notices.

```sh
node scripts/art/build-icon-paths.ts            # writes src/ui/icons/icon-paths.ts
node scripts/art/build-icon-paths.ts --check    # exit 1 when icon-paths.ts is stale (verify gate)
node scripts/art/render-icon-sheet.ts           # contact sheet: reports/art/icon-sheet.png
node scripts/art/build-icon-paths.ts --help     # every art script has --help; a bad flag is exit 2
```

The generated file of the shipped 19 icons is about 39 KB. Storing layers and stroking them at raster
time would be smaller but moves work onto the device; the flattened paths are kept.

## The Icon component and the rasterizer

- `icon-raster.ts`: `getIconUri(name, sizePt, pixelRatio)` rasterizes once per name and pixel size and
  caches for the app's lifetime (a module-level `Map`). The mask colour is opaque white in Skia's own
  colour form (`Float32Array.of(1, 1, 1, 1)`), never shown: `tintColor` paints it.
- `icon.tsx`: `<Icon name color size testID />` renders a native `Image` with `tintColor={color}` and
  `width = height = size`. It is decorative (`accessibilityElementsHidden`,
  `importantForAccessibility="no"`): the button or row around it carries the label, so VoiceOver and
  TalkBack read the action, not "image". Raw `Image` from react-native is allowed only in this file
  (typescript-and-lint-rules' ESLint zone).
- ui-component-library's controls take icons as a slot `(look: { size, color }) => ReactNode`, and
  `Icon`'s props spread straight in: `icon={(look) => <Icon name="plus" {...look} />}`.

## Sizes and colours

- Sizes are design tokens of the app, not of this skill. Keep a short list (for example 16 inline,
  20 rows, 24 buttons and bars, 28 to 32 empty states) and never scale an icon to fill a touch target:
  the target grows (44 x 44 pt on iOS, 48 x 48 dp on Android), the icon stays.
- Colours come from the theme (`theme.colors.text`, `onPrimary`, `danger`, `textMuted`), never a
  literal, so dark mode and every palette apply.

## Multi-colour glyphs

An icon is one colour. A glyph that needs two (a filled rating star with a darker edge) is two icons
stacked in the same box, each tinted from the theme: `star-fill` in `warning` under `star-edge` in
`text`; hollow is `star` alone in `textMuted`. Anything with three or more colours, or with colours
that are not theme roles, is a picture (brand-mark-and-pictures.md), not an icon.

## Mirroring in right-to-left layouts

Only icons that point along the reading direction flip: back, forward, chevron, undo, redo. `Icon`
mirrors them itself with `transform: [{ scaleX: -1 }]` when the layout direction is RTL (from
`useDirection()` in `src/i18n/direction-context.tsx`), so no call site can forget. Play, clocks,
checks, stars, the lock, the brand mark and pictures never flip. Which names are directional is
**rtl-and-direction's** rule (`directional-icons`, defaults back, forward, chevron, undo, redo, in its
`contracts/rtl.json`); this skill keeps `DIRECTIONAL_ICONS` generated from the layers' `"directional"`
list (`check-icons` fails `icon-set` when they differ).

## Tests: unit and golden

- **Unit project** (jest-expo): Skia's JSI module does not load ("Native Skia Module failed to
  correctly install JSI Bindings!"). The canonical root `jest.setup.ts` (unit-and-component-tests'
  `skia-unit-mock` rule) mocks `@shopify/react-native-skia` centrally: every component an inert
  `Skia<Component>` host element that keeps its props, every `Skia.*` call an inert value. Under it
  `getIconUri` returns a placeholder URI, so any screen showing an `Icon` renders. Never add a partial
  local `jest.mock('@shopify/react-native-skia', ...)` in a test that only renders: it replaces the
  central mock. `icon.test.tsx` proves mirroring, size and that the icon is hidden from screen readers.
- **Golden project** (CanvasKit, `*.golden.test.ts`): `icon-raster.golden.test.ts` rasterizes every
  entry to a real PNG data URI and proves the cache.
- `check-icons` samples every generated path against its layers without Skia (a winding-number grid,
  0.2-unit edge tolerance), so a hand-edited or stale path fails even when `build-icon-paths.ts` was
  not run.

## Adding or changing an icon

1. Draw it in the set's style: 24 grid, the set's stroke widths, round caps and joins, one colour, no
   text, readable at 16 pt. Look at its neighbours in [icon-catalogue.md](icon-catalogue.md).
2. Add its layers to `design/icon-layers.json` under a kebab-case name. Only an arrow that points along
   the reading direction goes into `"directional"`.
3. `node scripts/art/build-icon-paths.ts`, then `node scripts/art/render-icon-sheet.ts`, and look at
   `reports/art/icon-sheet.png` (open it with the Read tool): every icon must be crisp, centred,
   not filled solid by mistake, and match its neighbours' weight.
4. Run the checks. A new icon is a design change: say so in the report and include the sheet.

## If the app does not use Skia

The pipeline needs `@shopify/react-native-skia` (2.6.2 in the canonical stack) in the app. An app that
cannot take it keeps the same source of truth (the layers file and the generated paths) and draws each
path with react-native-svg's `<Path d fill>` inside its own `Icon` (the one place that does so); it
loses the measured list performance above. `check-icons` needs no allow-list entry for
react-native-svg. The layer model, the generator's flattening (run in Node, not on the device) and the
checks are unchanged; the app icon pipeline needs Skia in Node only (`render-app-art.ts` loads
CanvasKit), so it still works.

## What check-icons cannot see

The source bans are text scans. Their limits, by design (a review covers them; growing the patterns
would make them fragile):

- **Icons drawn with react-native-svg.** The package is allowed for charts and illustrations, so an
  `<Svg><Path/></Svg>` used as a button glyph passes. Reviewers look for `Svg` at icon sizes or inside
  a control's icon slot.
- **Escaped emoji.** `no-emoji` finds literal characters (one problem per line). `'\u{1F389}'`,
  `String.fromCodePoint(0x1f389)` or an emoji assembled at run time is not seen. It flags emoji
  presentation only (a character drawn as an emoji by default, or any pictograph followed by VS16
  U+FE0F); text-presentation symbols that render as font glyphs (`↔`, `✔`, `♠ ♥`, `⚠` without VS16,
  `©`, `™`) pass, so arrows and card suits stay usable in copy and in games.
- **Icon sets outside the list.** `no-icon-library` knows the common packages (the Expo and
  react-native-vector-icons families, every `@react-native-vector-icons/*` package, `expo-symbols`,
  Lucide, Phosphor, Heroicons, Feather, Tabler, Hugeicons, Iconsax, Remix Icon, Font Awesome). Any
  other icon package is caught in review.
- **Images reached indirectly.** `no-image-file` sees image files under the source folder and import
  or `require` specifiers ending in an image extension; a URI string built at run time or an image
  loaded from a package's own assets is not seen.

## What was verified

On 2026-10-10 (Node 26.4, Skia 2.6.2 on CanvasKit, a scratch copy of the reference Expo SDK 57 app):
the 19 shipped icons flattened without errors and the contact sheet was inspected; `--check` passed on
an unchanged set and failed after a one-coordinate layer edit; `check-icons` passed (coverage sampling
found no false mismatch on the new set); `Icon`, the rasterizer and the golden tests passed under the
canonical Jest projects. Flattening faithfulness was measured in the source app (design layers drawn as
SVG in Chrome against the flattened paths: 3 of 442,368 pixels differed, pixelmatch threshold 0.2).
Not verified here: rendering on an Android device (no native build in this pass).
